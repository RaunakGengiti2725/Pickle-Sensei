## Enforced invariants (tested)

- Server persists client scores verbatim with the full version vector; unknown scoring-model versions are rejected, never guessed.
- Canonical score sync accepts only an explicitly released scoring model tied to a 100%-active SHA-256 model bundle, dataset snapshot, locked evaluation-report hash, coach-validation reference, releasing admin, and the exact submitted shot-config version. Seeded `validating` configs and known-but-unreleased versions are rejected; a fresh database has zero active scoring models.
- Every shot sync carries the permit reserved before inference. Shot/detail/rollup persistence and permit consume (`scored`) or release (`low_confidence`) commit atomically.
- Replayed shot syncs succeed only when the full schema-normalized payload matches the SHA-256 bound to the canonical write. This exact retry remains valid after model retirement. Cross-user, reused-permit, changed-analysis, and mismatched-id collisions are rejected; any losing reservation owned by the caller is released without consuming a rating.
- PostgreSQL enforces the one-shot/one-permit relationship in both directions for new successful ratings; arbitrary client rating UUIDs cannot finalize a permit.
- Idempotent everything offline-first touches: exact replayed sync batches accept without duplicates; session create by client UUID.
- Ownership: stranger with a valid token + your UUID gets 404.
- Cloud upload impossible without cloud-sync consent (403 before any storage code runs).
- Deleted account: access revoked immediately; re-bootstrap returns 410.
- Access: exactly two lifetime free successful ratings; abstentions, `unknown`/`awaiting_model`, failures, cancellations, unsupported devices, and incorrect recognition release their reservations. Cloud deep is unavailable until a validated worker exists and returns typed 501 without stranding a reservation. Because the current camera cannot produce a validated accepted rating, it does not decrement the allowance; the third future successful-rating attempt is hard-gated unless an entitlement is active.
