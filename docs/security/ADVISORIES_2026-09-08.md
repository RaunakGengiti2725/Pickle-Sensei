## 8. Acceptance (H04-01-AC1 — "audits executed and every advisory has a disposition")

### 8.1 What the manifest command's exit code means

The manifest command (§2 #3) writes `pnpm.json` with `pnpm audit --json` and then `mobile.json`
with `npm audit --json` inside `apps/mobile`. Run verbatim it produces both reports and its
shell status is **1**, because `npm audit`'s exit code encodes _whether advisories exist_ (1 = at least one advisory
at or above `audit-level`), not whether the audit ran. It would be 0 only in a tree with zero
advisories — i.e. only if the three accepted-risk advisories in §4 were removed, which §6
shows cannot be done safely today. The package objective explicitly foresees this outcome
("document accepted risk otherwise"), so the criterion H04-01-AC1 grades is the sentence
"audits executed and every advisory has a disposition", and that is what §8.2 checks. The raw
exit code is recorded here and in the acceptance record's `note`; nothing in this review
changes `npm audit`'s arguments, `audit-level`, or exit status.

### 8.2 Criterion check (VERIFIED, §2 #16)

The manifest command verbatim (preceded by `mkdir -p` because `artifacts/` is git-ignored),
followed by a check that exits non-zero unless all of the following hold:

- (a) **audits executed** — both reports parse as JSON and are well-formed audit output
  (`metadata.vulnerabilities` and `metadata.dependencies` present, no `error` object). A
  missing file, an empty file (pnpm writes nothing when the registry is unreachable), or npm
  error JSON (`{"error":{"code":"ECONNREFUSED",…}}`) fails here.
- (b) **every advisory has a disposition** — for every GHSA id in either report there is a
  `### <n> GHSA-… ` heading in this document, and the Markdown table under that heading (up to
  the next `##`/`###` heading) contains **exactly one** row whose first cell is `Disposition`,
  and that row's second cell **begins with** `**UPGRADED**`, `**ACCEPTED RISK**`, or
  `**NOT APPLICABLE**`. The check parses table rows (`| label | cell |`), it does not search
  the section for keywords — a `PENDING`/`TBD` cell is missing even if another row quotes an
  allowed word or the rationale negates one (`not **UPGRADED**`); a duplicated, deleted, or
  keyword-later-in-the-cell row is missing; a demoted (`####`) heading is missing.
- (c) **no stale section** — every `### <n> GHSA-…` heading in this document names an id that
  the current reports still contain (a disposition for an advisory the audits no longer report
  means the document no longer describes the tree and must be re-reviewed).
- (d) **remediation floors are real** — every `Remediation floor` row names a leading
  `pkg@version` token (scoped packages allowed) whose version is a full semver, whose package
  the mobile audit reports, and which does **not** satisfy that package's audited
  `vulnerabilities[pkg].range` (semver from `apps/mobile/node_modules/semver`, installed by
  `npm ci`; the check fails if it is absent rather than guessing).

The script always writes `artifacts/advisories/disposition-coverage.log` (creating the directory
first) so a failing run leaves evidence, and its own exit status is the sequence's exit status
— no pipeline, `tee`, or `|| true`.
