## Binding product direction

**Validated 3D Analysis replaces the current primary analysis system. It is not a permanent parallel experiment, optional visualization, secondary mode, or future add-on.** The intended final state is:

`CURRENT 2D PRIMARY ANALYSIS -> RETIRED / FALLBACK-ONLY`

`NEW 3D ANALYSIS -> PRIMARY CANONICAL ANALYSIS EXPERIENCE`

The replacement includes reconstruction, comparison, supported coaching, modelled corrections, Result integration, navigation, state, persistence, tests, and release routing. Preserve the 2D implementation temporarily as the shipping safety net, regression baseline, and archive reader. Retain a fallback after cutover only for a documented technical or historical-data need. Do not maintain competing primary journeys or introduce a user-facing 2D/3D engine chooser.

The three synchronized views belong to ONE analysis: **actual reconstructed motion**, **matched reference**, and **modelled corrected motion using the player's own geometry**. Generated motion must remain distinguishable from the recording. None of these views may invent measurements, create an additional rating, or silently change history.

This direction supersedes the earlier optional same-view-comparison recommendation and any older statement that 3D is outside the intended analysis product. It does not authorize an immediate release. Keep shipping behavior safe until the separate gates below pass. A scoped architectural replacement is authorized; unrelated rewrites, cosmetic churn, unsupported physics, and weaker gates are not.

### 2. One processing plan, one evidence graph, three motion views

Build one canonical analysis coordinator around the existing capture, entitlement and transaction boundaries. The following names are proposed contracts, not claims that implementations exist:

```text
Recorded capture + immutable observations + owner scope
  -> resolveAnalysisPlan(release policy, device, input envelope)
  -> approved reconstruction adapter + coordinate/identity reconciliation
  -> raw estimate + validated temporal/kinematic estimate + uncertainty
  -> shared motion events and supported actual-motion measurements
  -> qualified reference selection + bounded phase correspondence
  -> supported differences -> one prioritized issue/coaching graph
  -> approved actual-motion score or explicit score abstention (one invocation)
  -> constrained modelled-correction branch (when authorized; never scored)
  -> one atomic AnalysisOutcome/artifact manifest/rating-outbox commit
  -> one AnalysisPresentationModel + one canonical Result experience
```

`resolveAnalysisPlan` selects the processing policy BEFORE expensive work and freezes its version for the run. A new recording cannot be rejected merely because a 3D sidecar has not yet been produced. After reconstruction, capability evaluation decides what this evidence supports. Historical reading is a separate decision based on the stored record, never a re-run of the current global engine selector.

The correction branch must complete or return an explicit abstention within the overall latency budget; record that status in the same atomic outcome. A correction timeout/failure must not discard a valid actual-motion result or leave hidden work counted as complete. Count these failures against correction coverage and performance gates.

The actual, reference and modelled views share a clock/controller and issue graph. They are not three scoring pipelines. No renderer may recompute faults, infer handedness, choose a different priority, or substitute its own coaching message. Consolidate the duplicated checkpoint/phase and side-selection rules into versioned domain mappings.

Do not freeze the old scoring algorithm merely to avoid a schema change. New 3D feature semantics, target ranges, calibration and reference-dependent scoring require new definitions and versions. Existing Gaussian scoring, priority arithmetic or cue templates may be retained only where their semantics and validation support that reuse. The existing 0.65 heuristic confidence, 120 ms pairing window and 1.5 bone-ratio software bound are NOT 3D uncertainty or anatomical acceptance criteria.

### 6. Matched references and meaningful differences

Selection order is mandatory: **eligible qualified-coach-reviewed exemplar -> eligible player's-own-best prior motion -> no reference**.

A coach exemplar needs verified, active reviewer identities, qualification scope, explicit exemplar suitability, rights for the intended display/use, and evidence bound to the exact motion artifact. It does not need a score from the current unvalidated app to be a qualified exemplar. A name string or self-declared “coach-reviewed” flag is insufficient.

An own-best candidate must belong to this owner and athlete, predate the current attempt, retain adequate original evidence, and meet an approved selection and version-comparability policy. **Legacy 2D scores are not inputs to own-best eligibility or ranking.** Require either a prior actual 3D score under the relevant G-S-released definition or a qualified review of that actual 3D attempt; the selection rule itself needs G-CMP validation. If neither exists, own-best is unavailable.

A reference is a suitable example, not a universal perfect pose. Keep its own body geometry. Normalize only factors validated as irrelevant to the particular comparison; do not force anatomically different athletes into the same limb lengths or treat style variation as a defect.

### 8. Modelled correction of this athlete

This is a separate required capability with its own gate, not an exemplar substitution or cosmetic animation. Input is the accepted actual reconstruction, its individual geometry and uncertainty, and a set of supported issues with approved correction operators/target intervals. Output is a separately labelled, versioned generated artifact.

Use constrained minimal-change optimization or another empirically justified method. Preserve body proportions, handedness, stroke identity, unaffected style, original observations and unsupported joints. Target a coach-supported acceptable interval, not an arbitrary ideal coordinate. Record the cost terms, feasible ranges, solver/version, seed, residuals and convergence status.

Define the allowed joint/region/time modification mask BEFORE solving. Kinematic dependencies can require adjacent joints or timing to change; such expansion needs an explicit approved operator, evidence and explanation. Outside the permitted mask, motion values remain equal within the locked numerical tolerance. If keeping unaffected motion and satisfying anatomy is infeasible, abstain instead of silently broadening the correction.

Enforce joint constraints, bone-length invariance, collision/self-intersection limits, continuity of position and velocity, supported foot contacts, phase order, and bounded transition derivatives. Timing corrections have their own monotonic time map; generated timestamps are not observed capture timestamps. Do not smooth discontinuities across an identity break or add missing evidence.

Empty or unsupported correction sets produce no-change/abstention, not a different default animation. Uncertain body regions inherit their uncertainty and remain unaltered. Distinguish equality of motion tensors from the necessarily different generated-artifact metadata.

Validation must include independent mechanical checks and blinded qualified-coach review of feasibility, direction, preserved motion and usefulness. Where feasible, compare with separately recorded coach-guided performances by the same athlete; these are examples of feasible changes, not a unique “correct” trajectory. Optimizing the old score or asking the same inference model whether its correction is good is circular validation.

**Modelled correction is never scored, counted as practice, selected as an observed own-best, synced as a real rating, or exported as ground truth.** It cannot show a projected score/DUPR improvement. Enforce known artifact roles/lineage through types, runtime checks, storage and server validation; test relabelled known-generated IDs/digests and unknown lineage. An untrusted client field cannot grant observed provenance. These controls do not magically authenticate arbitrary video or detect every forgery; any stronger origin-assurance claim needs its own implemented and tested trust boundary.
