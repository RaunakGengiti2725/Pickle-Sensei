## Reproduce and verify

Run from the repository root:

```sh
npx --yes deno@2.5.6 run --config supabase/functions/api/deno.json \
  --lock=supabase/functions/api/deno.lock --frozen --node-modules-dir=none \
  --allow-read --allow-run=git \
  tools/release-policy/build-1.0-operational-2d-build4.ts \
  --evidence-sha256 ef3a1f536641397f7cf17395674bed366b9c9ebb5cec12ae4720f1c28b636ee5 \
  --check
```

For first-time generation, omit `--check` and add
`--allow-write=docs/release-policy`. `--out-dir` can direct output to a
disposable verification directory. The builder checks the pinned source and
current HEAD, rejects uncommitted changes in bound artifacts, checks the
explicit evidence digest, validates the shared policy contract, and refuses to
replace an existing file with different immutable bytes. A changed analyzer
or evidence snapshot requires a new policy version.

The production-owner install, separate mechanics and benchmark approvals, and
activation are distinct operations. Preserve the previous policy and approval
history. After any authorized activation, save the live
`read_analysis_release_policy()` result and run
`tools/release-policy/verify-authority.ts` against it. A synthetic approval
used for local verification is never production approval.
