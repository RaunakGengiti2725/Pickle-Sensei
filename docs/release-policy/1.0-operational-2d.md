## Honesty notes the owner accepted

- The mechanics calibration (`config/v1.ts`) describes itself as the
  blueprint's "starting hypothesis for expert validation". The policy names it
  exactly that; the release readiness report it cites makes no accuracy claim.
- The 1.0 analyzer produces **no technique benchmark**: the pipeline has no
  benchmark stage and Result always shows "Technique benchmark unavailable —
  separate validation is required". The schema requires a benchmark section,
  so it binds the withholding contract and declares the narrowest boundaries
  the contract allows (`[2, 2.25]`, width 0.25, step 0.25, nominal coverage
  0.5). Those numbers describe an output nothing in 1.0 can publish.
- Only the side camera view ships (`AnalyzeScreen` runs the analyzer with
  `cameraView: 'side'`); `rear_oblique` is deliberately not a supported input.
- A fixture input is never eligible; an unsupported observation is `unsupported`.

## Stopping new ratings

`select public.deny_new_analysis_authorizations('<operator>')` stops new
authorizations without withdrawing the policy;
`select public.withdraw_analysis_release_policy('<sha256>', '<operator>')` is
irreversible. Both are database-owner only.
